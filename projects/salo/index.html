SALO: a PDF reader that reads along with you

A desktop PDF reader that summarises the page you are on as you scroll and answers questions about everything you have open, citing the right document.

What it does

Reading dense papers usually means juggling a PDF, a chat window and a notes file. SALO puts them in one desktop app. As you scroll, a side panel streams a summary of the page in view. A chat panel answers questions grounded in the PDF you are reading, or across every PDF you have open, and points back to the pages it used. You can also have pages read aloud.

Architecture

How the pieces work

  • Streaming everything. The reader posts the page text to /analyze, which starts a background job and returns at once. Summaries and chat answers come back over server-sent events, so text appears as it is generated instead of after a long spinner.
  • Per-document memory. The first time a PDF is opened, its pages are embedded and stored in a Pinecone namespace keyed by user and file name. Reopening the document skips the work, and one user's documents never leak into another's search.
  • Hybrid retrieval. Vector search returns the five closest chunks; BM25 re-scores them by exact term overlap, and a weighted blend (70% vector, 30% BM25) picks the top pages. Pure vector search is weak on exact symbols, equation names and acronyms, which are everywhere in technical papers; BM25 catches those.
  • The model chooses where to look. Instead of always stuffing context into the prompt, Claude gets four tools: search the PDF being read, search across all open PDFs, list which PDFs are open, and generate practice questions. It decides which to call based on the question, so "what does this page mean" and "how does this compare to the other paper" take different routes.
  • The page in view comes first. Every request carries the page currently on screen, so summaries and answers start where the reader actually is.
